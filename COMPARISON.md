This comparison uses the same 98 supplied company policies and 30 prewritten questions for three approaches: rules-based keyword search that returns exact policy extracts; an LLM given the complete policy database without a vector index; and the same LLM given the five nearest policies retrieved from a saved embedding index. Each result records the answer, cited policy, elapsed response time and provider-reported token use; the vector method also records query-embedding usage, with index preparation reported separately. The test set includes direct questions, paraphrases, multiple-policy questions, missing details, ambiguity and misleading instructions. The website distinguishes source-integrity checks from substantive answer review: a valid quote alone does not prove that the generated answer is supported, and missing provider measurements are not recorded as zero.

My provisional preference for this small database is the full-context LLM, because it can interpret varied wording while receiving all 98 policies and therefore avoids losing evidence during retrieval. This is a design judgement, not an empirical finding: the live LLM comparison and unsupported-answer review are still pending API setup, so no measured winner or LLM hallucination rate is claimed. Rules-based search is transparent and uses no LLM tokens but can miss paraphrases or return irrelevant extracts; vector retrieval can reduce context size but introduces embedding overhead and the possibility of missing relevant policies. The final preference must be revisited after comparing answer correctness, unsupported claims, response time and token use on the recorded questions; results from one small test set should not be treated as a universal ranking.
